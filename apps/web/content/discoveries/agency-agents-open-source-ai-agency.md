# agency-agents: an open-source AI agency with 147 specialist roles

Most "AI agent" projects are either toy demos or vague promises with a landing page doing all the heavy lifting.

This one is different.

`agency-agents` is a GitHub repo that packages 147 specialist agent roles into something closer to a working digital agency. Frontend agents. Community agents. Research agents. Strategy agents. Not every one of those roles is production-ready. Doesn't matter. Someone bothered to operationalize the org chart.

## The core idea

The repo turns a fuzzy idea — "what if AI could run more of the agency?" — into a concrete library of role definitions.

Most teams still talk about agents like they are one magic worker with infinite range. That model breaks fast. Writing is not QA. QA is not outreach. Outreach is not analysis. The more your system starts to matter, the more specialization shows up.

So a repo with 147 agent roles is less interesting as software than as evidence. It's proof that the market is drifting toward agent teams, not single super-agents.

## Why it matters for Applied Leverage

Applied Leverage is already built around this bet.

We don't need one giant assistant that "helps with everything." We need reliable operators with clear scopes, handoffs, memory boundaries, and decision rights. That's the difference between a demo and a system you can actually sell.

The repo is also useful as a pattern library. Not because we should copy its exact role list, but because it forces the right question: where should a founder stop being the router?

Once you start naming the roles, you start seeing the bottlenecks.

- Who owns research?
- Who owns delivery QA?
- Who owns client follow-up?
- Who owns content repurposing?
- Who owns escalation?

Founders usually hold all five in their head at once. That's why the business feels "busy" all the time. Busy is often just unassigned work wearing a costume.

## The catch

A giant list of agents can also become pure cosplay.

147 roles sounds impressive right up until you ask how they coordinate, what context they share, how conflicts get resolved, and which outputs are actually trusted. If the answer is "the founder checks everything," congrats, you built a more expensive to-do list.

There's also a maintenance problem. Every role you define becomes something you need to test, tune, and occasionally kill. Most stacks do not need 147 agents. They need five that actually finish the job.

Still, this repo gets one important thing right: specialization is not a bug in agent systems. It's the whole game.

If you're still trying to make one general-purpose bot run your company, you're not building an AI team. You're building a future disappointment.
